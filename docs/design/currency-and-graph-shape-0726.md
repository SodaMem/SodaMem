## 0. 一句话

"哪条记忆是当前值"这个能力,我们的代码**全套都在、产出为零**。根因不是配置关闭,
是**谓词规范化把属性名和取值揉成了一个词**,导致同一件事的两个版本按构造拿不到同一个键。
业界没有一家用谓词字符串做匹配键——Graphiti 用实体对,mem0 干脆把匹配砍了。

## 1. 实测发现(冻结店 `longmemeval_s_500_Hobs`,零 LLM 零网络)

### 1.1 取代机制产出为零

| 机制 | 代码 | 500 家真店 |
|---|---|---|
| `SUPERSEDES` / `CONTRADICTS` 边 | ✅ 实现完整 | **0 条 / 500 家** |
| status 非 active | ✅ 实现 | **0 条,全 active** |
| `valid_until` | ✅ 一等字段 | **0 / 469** |
| `document_time` | ✅ 实现 | 冻结店 0%,**0704 后新店 93%** |
| `occurred_start` | ✅ | 7-10% |
| `valid_from` | ✅ | 54-56% |

`derived_currency` 依赖 `valid_until`,而 `valid_until` 全域为 0 —— **它在空转**。

### 1.2 根因:谓词把属性名和取值揉在一起

```
问:"我打算住夏威夷哪里?"   金答:Oahu
谓词:staying_on_oahu       ← 属性名 + 取值 融合
```

用户改说住 Maui → 谓词变 `staying_on_maui`。**两个版本按构造不可能匹配。**

实测:**429 个不同谓词 / 469 条事实 = 91% 唯一**。取代检测的前提
(`同主语 + 同规范谓词`)因此几乎永不成立。

### 1.3 信息没丢,在 `entity_roles` 里

```json
{"entity_roles": {"subject": "user", "island": "oahu", "gift_type": "customized photo album"}}
```

取值是分开存的。按角色名分组,**26.5% 的角色有多个取值**——候选版本链在这里。

### 1.4 「改主意」与「多值集合」结构上无法区分

```
role=island → {kauai, oahu}                      ✅ 真版本链(金答=oahu)
role=item   → {funko pop, 笔记本内胆, 拍立得}      ❌ 三样都有效
```

这是语义判断,**任何确定性键都做不到**。任何声称能做到的方案都在自欺。

### 1.5 时序可得

Kauai@2023-05-22 → Oahu@2023-05-25,取自 `source_spans.session_time`。
即使 `document_time` 为 0 的老店也能排序(`document_time` 的定义就是
"最后一个源片段的 session_time",可现算)。

## 2. 图形状:为什么 Graphiti 的键在我们这里退化

**实测:4700 条事实,`subject_entity_id` 只有 `entity_user` 一个值(100.0%)。**

| | 图形状 | 实体对键 |
|---|---|---|
| Graphiti | 一般图 `(实体A)--关系-->(实体B)` | `(源,目标)` 组合空间大 |
| 我们 | **完美星形** `(user)--谓词-->(对象)` | 退化为 `(对象)` 单键 |

连纯实体间事实(「欧米茄 1848 年由 Louis Brandt 创立」)也被压成主语=user
的星形边。**信息在,结构没了。**

### 2.1 退化后依然可用(实测)

排掉无宾语实体的事实后,按**宾语实体**分组:

| 指标 | 值 |
|---|---|
| 有宾语实体的事实 | 1750 / 2814 = **62%** |
| 其中落入多成员组 | **84.1%** |
| 最大组 | **17** |
| 中位组大小 | **2** |

样本是连贯话题簇(`entity_omega` 11 条全关于那块表、`entity_scythe` 11 条全关于那款桌游)。
**中位 2 / 最大 17 正是 Graphiti 模式要的候选池尺寸**——小到可交给 LLM 裁决。

### 2.2 真图(非星形)的价值

```
现在:  user --owns_omega_seamaster_watch--> Seamaster
       user --omega_founding_year_founder--> Omega        ← 硬塞进星形

真图:  user --owns--> Seamaster --made_by--> Omega --founded_in--> 1848
```

1. **多跳推理**——"我那块表的厂商哪年成立",用户从未把两件事连起来说过也能答
2. **实体对键真正生效**——`(Seamaster, Omega)` 上的版本链才有意义
3. ~~**🌟 跨用户共享去重**~~ —— **0726 撤回,见 §3.1**
4. **社区发现**——相关实体聚类

代价:抽取多一层、图变大、**LME 基准可能不奖励**(问题都是"我说过什么"的用户中心视角)。

## 3. 业界对照(源码级核实,2026-07-26)

| 框架 | 匹配键 | 判定方式 | 写侧/读侧 |
|---|---|---|---|
| **Graphiti** | **`(源实体uuid, 目标实体uuid)` 确定性** | 小候选池内 LLM 判重复/矛盾 | 写侧,标 `invalid_at` **但不删** |
| mem0 v3 | **无** —— `DEFAULT_UPDATE_MEMORY_PROMPT` **已成死代码,全仓零引用** | md5 精确去重 + `linked_memory_ids` | **都不做** |

| Honcho | 无(append-only) | 生成 `ContradictionObservation` **新节点,不覆盖** | **读侧**(下游 LLM 看时间戳自行权衡) |
| Redis agent-memory-server | hash 精确 + 向量距离 0.35 | LLM 合并候选群 | 写侧 |
| **我们(现状)** | **规范谓词字符串** | — | **饿死** |

### 3.1 🔴 撤回一条论据:跨用户世界知识共享

原文把"跨用户共享去重"列为改星形图的最大收益。**两条独立证据推翻它:**

1. **实测**:100 家店 47,970 条事实,世界知识类占 32.3%(文本占 46.5% 字符),
   但**跨用户完全相同文本仅 2.30%**。LongMemEval 每个用户聊各自不同的合成话题,
   天然不重叠。(生产环境重复率可能更高,**但我们没有那个数据,不能拿来论证**。)
2. **业界**:**没有一家做跨用户世界知识共享/去重**。Graphiti 的节点去重候选检索
   硬编码按 `[node.group_id]` 过滤(`node_operations.py:439-446`),跨 group **永不合并**;
   mem0 强制 `user_id`/`agent_id`/`run_id` 分区,没有"全局无主"记忆的位置;
   Redis agent-memory-server 结构上留了口子(`user_id` 可选)但无去重代码。

两条互相印证:**大概率不是没人想到,是不划算。**

改星形图的正当性因此**只剩三条**:①解 external_info 稀释 ②实体间结构/多跳 ③少量省钱
(上界 $0.014/用户 ≈ 500 用户省 $7,且因部分世界知识答题必需,真实值远低于上界)。

### 3.2 抽取 schema 横向对照(源码级,0726)

| 框架 | 抽取单元 | 主语能否非用户 | 跨用户共享 |
|---|---|---|---|
| **Graphiti / Zep** | `(源,关系,目标,fact)` 三元组 | **是**——通用实体图,**无 "User" 特殊节点类型**,speaker 亦为普通节点;edge prompt 明确鼓励找第二实体锚定 | 无(group_id 硬隔离) |
| **Cognee** | 三元组 | **是**——纯通用知识图谱,无 user 概念 | 未细查 |
| **Redis agent-memory-server** | 自由文本+实体标签 | **是**——few-shot 直接是纯世界知识 | 结构上可能,无代码 |
| **Honcho** | 自由文本 observation | **是**——对称 peer 模型 | 无 |
| **mem0** | 自由短句+`attributed_to` | 半支持(语义主语可非 user,归属标签仍 user/assistant 二元);**图模块已从 OSS 整个移除** | 无(强制分区) |
| **我们(现状)** | 三元组 | **否——100.0% entity_user** | — |

**我们的星形是真正的异类。** 另:"用户中心 vs 通用图"这个取舍**业界无一家公开讨论过**,是隐性选择。

**关键结论三条:**
1. **没有一家用谓词字符串做键。** 91% 唯一不是 bug,是"用字符串相等做语义判断"的必然结果。
2. **主流不是纯 LLM 也不是纯确定性,而是"确定性结构键收窄候选池 + LLM 在小池里裁决"**
   (Graphiti 教科书实现)。
3. **严格的"读侧确定性 currency 派生"业界空白。** Honcho 最接近但它选择*不判断*。
   我们若做成是原创差异化,不是抄作业。

## 4. 两步方案

### 第一步:读侧分组呈现(便宜、零风险、先做)

**不判定谁取代谁**,只在 `get_context` 渲染时按**宾语实体**分组 + 时序标注:

```
island: kauai (2023-05-22) → oahu (2023-05-25)
```

| 属性 | 值 |
|---|---|
| LLM 调用 | **0** |
| 写入 | **0**(纯渲染层,存储不动) |
| 误杀风险 | **0**(不隐藏任何证据) |
| 先例 | Honcho 同路线 |
| 依据 | reader 已证明擅长此事(KU **97.2%**) |
| 门 | **必须过 S500**(改的是 reader 输入) |

**为什么不硬过滤**:硬过滤 = 账本里 board 全局时间排序那个 **47%→5% 灾难**的翻版。
只呈现结构,判断权留给 reader —— 这正是 ADD-only 哲学。

### 第二步:写侧小池裁决(贵、有前科、后议)

若第一步收益不足,再上 Graphiti 式:在**宾语实体键收窄出的小候选池**(中位 2/最大 17)
内让 LLM 判矛盾,标 `valid_until` + 边,**绝不删除或隐藏**。

⚠️ **前科**:mem0 做写时 ADD/UPDATE/DELETE 判定时 67.8,改 ADD-only 后 94.4 ——
**掉 26 分**。Graphiti 敢做是因为它**只标不删**。我们若做必须同样只标不删。

代价:ingest 每条事实多一轮 LLM(现 ingest 已 $0.0455/用户、输出占账单 65%)。

### 不做的事

- ❌ **不删除 maintainer 的 supersede 代码** —— 它没被判负,是被饿死。项目规则是
  "验证输家的旗+代码路径删除",它从未被 A/B 过(config 自注 `pending A/B`)。
  但应加 pin 测试锁住"冻结语料上 supersede 边恒为 0",防止抽取改动后**静默激活**。
- ❌ **不做 memory decay** —— 需要长历史规模基准,我们没有。且时间加权在本项目
  已烧过两次(board 排序 47%→5%、tfix 店 −12)。
- ❌ **不接外部图数据库** —— 每用户 ~470 事实 / ~2600 边是玩具规模;边 96% 是
  结构索引(MENTIONS/EVIDENCES/SUBJECT_OF/OBJECT_OF),语义边为 0。
  **空图换更快的引擎还是空的。** mem0 v3 已删掉外接图库(~4000 行)独立佐证。

## 6. 🔴 0727 门结果:第一步方案对 KU 无效,假设被证伪

第一步(读侧分组呈现)已实现并挂旗 `ReaderConfig.role_timeline`(默认关)。
KU 全类别 72 题配对 A/B,同一 HEAD、同一冻结店、两臂只差这一个变量。

### 6.1 结果

| | OFF | ON |
|---|---|---|
| KU 正确 | 68/72 = **94.4%** | 69/72 = **95.8%** |
| 回归(OFF 对 / ON 错) | — | **0** |
| 增益(ON 对 / OFF 错) | — | 1(q399) |
| McNemar exact p | — | **1.000** |

**那唯一的"增益"不成立**:q399(按揭预批额度)的 timeline 产出 **0 行**,
块根本没进它的 prompt。这是模型抖动,不是功能。

**净效应:0 增益,0 回归。**

### 6.2 为什么是零 —— 比结果本身更重要

KU 剩下的 4 道错题,**没有一道是版本链形状**:

```
q399  按揭预批额度 $400,000       timeline 0 行   数量题
q434  每天写代码多久 约两小时       timeline 0 行   数量题
q421  在现公寓住了多久 3 months    location: Tokyo, Harajuku → Harajuku(同地点不同粒度)
q451  旧球鞋放哪 鞋架              item: old sneakers → white sneakers → sandals(§1.4 的多值集合)
```

而干跑门标记为"金答在链尾"的 4 道真版本链题(q061 夏威夷、q071 琴行、
q410 镜头、q441 皮卡)——**OFF 臂全部答对**。

§4 引 "reader KU 97.2%" 作为"它擅长此事所以可以把判断权交给它"的依据。
实测把这条依据推到了终点:**它擅长到不需要这个块**。§0 说的"能力全套都在、
产出为零"对 supersede 边成立,但"产出为零 ⇒ 分数被压"这一步是推断,不是实测,
现在这一步被证伪了。

### 6.3 派生结论

1. **不跑全量 500。** 效应量为 0,基准噪音 ±1.5%,再花七倍成本只能买回同一个零。
   安全性已在 72 题上验到 0 回归。
2. **第二步(写侧小池裁决)的正当性同步减弱。** 它比第一步贵得多,而第一步已经
   证明"把版本链呈现给 reader"在 LME 上没有可捡的分。写侧裁决要立项,必须先找到
   一个第一步没能覆盖、且真实存在的失败样本 —— 目前一个都没有。
3. **KU 真正的压分点是数量/时长推理**(4 题里 2 题纯数量、1 题时长差),
   与时效性无关。这才是 KU 该开的下一张 ticket。
4. **`role_timeline` 旗保持默认关。** 代码小、有测试、零回归,留着不碍事;
   但它在 LME 上已被判为 inert,任何"再试一次"必须先给出新假设,不能重跑同一实验。
5. LME 是"我说过什么"的用户中心问答,§2.2 早就提示"基准可能不奖励"结构性改进。
   **本次结果不能外推到生产 `get_context`** —— 那里没有基准,也就没有证据,
   两个方向都不能声称。
